# 决策记录

只记录当前有效的决定、理由与被放弃的方案。决定被推翻时直接改写原条目。

## D1 Windows 原生 + Go + MyGo

**决定**：用 Go 与 MyGo 构建 Windows 原生划词翻译工具，不使用 Electron/WebView。

**理由**：常驻托盘、低内存、启动即用；MyGo 提供窗口、托盘、快捷键、剪贴板与打包。界面按 Windows 11 Fluent 规范自绘。

**放弃**：Electron（包体与内存大）；Web 技术栈（与系统集成割裂）。

## D2 API Key 放 Windows 凭据管理器

**决定**：Key 通过 `mygo.Secrets` 写入 Windows 凭据管理器，`config.json` 不保存密钥。

**理由**：Windows 凭据按用户加密，配置可安全分享或交给 agent 编辑，不需要像 macOS 自签名应用那样反复重新授权。

**代价**：agent 只能改服务地址、模型等非敏感字段；配置 schema 不包含 Key。

**放弃**：与 Kami 一样把 Key 明文放进 `config.json`（本项目配置可能被同步或分享）。

## D3 提示词采用材料/指令分离

**决定**：system = 用户可编辑提示词 + 材料合约 + 可信运行参数 JSON；user = 原文。

**理由**：划选文本可能包含「忽略以上指令」之类的内容。把原文限制在 user 消息，并明确它是材料而不是指令，可以防止任务被劫持；语言、输出格式等参数与材料分离，来源可信。

**兼容**：保留 `{{target}}`/`{{source}}` 占位符，旧自定义提示词继续可用。

## D4 统一错误分类，而不是展示原始报错

**决定**：所有服务错误包装为带类型的错误（HTTP 状态、服务错误码、配置错误），由 `ExplainError` 生成标题与下一步。

**理由**：翻译失败时用户需要知道「该改 Key、该重试、还是该缩短文本」，而不是一段服务商 JSON。

**放弃**：在 UI 里直接显示 `接口返回 401：...`。

## D5 配置是 agent 接口

**决定**：`config.json` 配套 `config.schema.json`，严格解码，支持热加载；应用每次启动写出 schema。

**理由**：用户和 coding agent 可以直接编辑配置文件，拼错字段或取值越界会明确指出位置；改完无需重启。

**放弃**：独立的 `config set/show` 命令；只做宽松反序列化。

## D6 多引擎并发与优先级回退

**决定**：默认按服务顺序回退；开启多引擎后并发请求所有已启用服务，卡片并列展示，可单独复制。

**理由**：不同场景需要不同引擎；失败时自动回退不打断翻译，对比时又能同时看到结果。

**限制**：截图只使用启用且支持视觉的 OpenAI Compatible 服务。

## D7 划词取词依赖 Ctrl+C + 剪贴板恢复

**决定**：发送 Ctrl+C 读取前台选区，读取后恢复原剪贴板；无法保存剪贴板时取消翻译。

**理由**：Windows 没有统一的跨应用选区读取接口；恢复剪贴板避免破坏用户内容。

**放弃**：读取 UI Automation 选区（应用覆盖不全、权限与兼容成本高）。

## D8 朗读使用 Windows SAPI

**决定**：通过 PowerShell `System.Speech.Synthesis` 朗读译文，可随时停止与重播。

**理由**：系统自带、无需额外依赖，支持中英文语音。

## D9 设置窗口与托盘并存

**决定**：保留图形设置窗口，同时托盘菜单提供常用开关。

**理由**：本项目面向日常划词翻译，设置项以服务、快捷键、触发方式为主，图形界面比对话式配置更直接；与 Kami 的「一切在面板里」不同。

**放弃**：只通过对话/Operator 修改配置。

## D10 模式是提示词预设

**决定**：内置翻译、润色、总结、解释四种模式，结构为 id、名称、提示词、语义（材料/指令）。`config.json` 的 `modes` 非空时替换整个列表。

**理由**：这些场景的差别只在提示词；同一条请求管线让新增模式不需要新代码。材料/指令区分保证原文里的指令不会劫持任务。非翻译模式沿用原文语言，避免润色中文时被自动目标语言翻成英文；自定义模式仍可用 `{{target}}` 指定输出语言。

**放弃**：为每个模式写单独的结果视图；在模式里绑定模型或服务。

## D11 追问保留原文与上一轮结果

**决定**：结果出来后可以继续追问，请求包含 system 合约、原文、上一轮结果和新的追问指令。

**理由**：多数调整是对结果的自然语言修正（更短、换语气、加一列），不需要重新描述原文。

**限制**：截图和多引擎对比模式不提供追问；追问不替换主结果，而是追加展示。

## D12 主题只做系统/浅色/深色

**决定**：主题取 `system`、`light`、`dark`，沿用 Windows 11 Fluent 配色；不引入 Kami 的多套社区配色。

**理由**：本项目面向 Windows 11 原生体验，系统明暗切换已经覆盖大多数需求；固定两套色板足以在夜间使用。

**放弃**：18 套主题与自定义颜色编辑（与 Fluent 设计语言冲突，维护成本高）。

## D13 双击也能取词

**决定**：双击单词与拖动选词共用同一条取词链路；单击只记录点击位置，不触发。

**理由**：双击选词是 Windows 上最自然的单词选择方式，只支持拖动会让单词查询显得迟钝。判定使用系统双击时间与 4px 容差，拖动仍要求 ≥8px 且按住 ≥40ms，避免误触。

**限制**：双击依赖目标程序自身的选词行为；在文件列表等没有文本选区的位置，Ctrl+C 读不到文本，不会弹出气泡。`HAYAMI_HOOK_DEBUG=1` 会记录手势与拒绝原因，便于排查 Windows 静默摘钩。

## D14 Linux/Wayland 原生集成与 CLI 单实例分发

**决定**：在 Linux 下优先使用 Wayland PRIMARY 选区（`wl-paste`）读取文本，全局快捷键采用左手主键位（`Alt+F` 划选、`Alt+D` 输入、`Alt+S` 截图），窗口采用托盘贴边吸附面板，并提供单实例 CLI 调度管道（`-s`、`-i`、`-c`、`-t`）。

**理由**：Wayland 客户端隔离无法获取全局光标绝对坐标或注入全局鼠标钩子；PRIMARY 选区划选即进入，无需注入 `Ctrl+C` 侵入用户剪贴板；抽屉式面板和 CLI 管道既保证 0 剪贴板污染，又支持用户在桌面环境（如 KDE 快捷键）中灵活绑定。

**放弃**：强制使用 evdev / `/dev/input` 监听鼠标（需要特权或额外用户组，且依然缺少屏幕绝对坐标）；在 Wayland 下盲目尝试光标跟随小气泡。

## D15 Wayland 选区监听保留 wl-paste --watch 并推迟纯 Go 协议栈

**决定**：在纯 Go（`CGO_ENABLED=0`）约束下，暂不在应用内从零实现 Wayland 原生选区二进制协议客户端（`zwp_primary_selection_v1` / `ext_data_control_v1` / `zwlr_data_control_manager_v1`），保留并加固现有的 `wl-paste --primary --watch` + X11 `xclip`/`xsel` + `pollSelection` 回退架构；详细评估见 `docs/wayland-selection-feasibility.md`。

**理由**：`zwp_primary_selection_v1` 仅向当前持有键盘焦点的窗口派发选区 offer，无法在后台监听其他应用的划词；后台监听必须依赖 `ext_data_control_v1` 或 `zwlr_data_control_manager_v1`，而 GNOME Mutter 明确拒绝向非特权客户端开放 data-control 协议。自研纯 Go 线协议解析与 `SCM_RIGHTS` 文件描述符传递需维护约 800–1,500 行底层代码，却仍无法在 GNOME 上免除轮询/快捷键回退；相比之下，`wl-paste --primary --watch` 已在 KWin 与 wlroots/Smithay 合成器上实现零空转唤醒。

**加固**：修复 `StdoutPipe` 与 `cmd.Wait()` 在取消时的竞态、启用独立进程组 `Setpgid` + `WaitDelay`、捕获有限长度 `stderr` 诊断日志、在 watcher 持续稳定运行 30 秒后重置失败计数，并通过可注入接口完成 `-race` 单元测试。
